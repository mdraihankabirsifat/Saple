Project guide

Frequently asked questions

How Saple handles public information, verified contribution access, moderation, privacy, and the boundaries of this academic project.

Saple is a database-focused academic platform for exploring companies, benefits, approved salary information, employee reviews, and interview experiences. It demonstrates relational data, authorization, verification, moderation, aggregation, and privacy-aware public views.

Anyone can browse the approved public information without signing in. Pending, rejected, and flagged contributions are excluded from public results.

An employee account may contribute only while it has a valid, active employment verification for the selected company. Administrator status does not automatically grant contribution rights. Every accepted contribution still enters moderation before publication.

An employee submits a request for a specific company using company-email or document-reference evidence. A moderator can verify or reject the request. Verified access expires after the configured period and never makes the private evidence public.

A user with the ADMIN account role reviews the private request metadata and records a verified or rejected decision. A rejection requires a reason.

Limited employment scope prevents one approval from becoming permission to post for unrelated employers. The current Saple implementation enforces the approved company; it does not yet store or enforce a separate designation scope. Designation-specific authorization is therefore future scope and is not presented as operational.

The Verified Salary Range uses approved salary records marked with verified contributor status. The Community Salary Range uses all eligible approved salary records under the current project query, including both verified and unverified approved records. Contribution counts provide essential context for both ranges.

New salary, review, and interview submissions start as pending. An administrator can approve, reject, or flag an allowed transition, and the status change plus its moderation-history record are written atomically. Only approved records appear publicly.

Public review and interview responses show an author name only when the contributor chose nonanonymous display. User IDs, email addresses, verification evidence, and moderation details are never included in public responses. Saple keeps internal ownership for authorization and accountability.

A signed-in user can open the report control on an approved public review or interview, choose a reason, and provide details. Administrators review reports separately and may use the audited submission-moderation process to flag or reject the reported content.

Enter the registered email on the Forgot Password page. When SMTP is configured, Saple sends a temporary, single-use reset link; it never emails the existing password. The link expires after the configured short period, which defaults to 15 minutes. Check spam or junk folders if delivery is delayed. This academic workflow demonstrates secure token handling but is not a production availability guarantee.

Saple publishes only eligible approved contributions. A newly listed company or role may have few or no records, and small samples should not be treated as representative. Directory coverage does not guarantee salary, review, or interview coverage.
